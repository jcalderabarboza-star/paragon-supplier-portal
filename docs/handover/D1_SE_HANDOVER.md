## 1 · What this platform is, and what it is not

**It is a fixture-only React/TypeScript single-page application that serves as the executable specification for a supplier collaboration portal over SAP S/4HANA.** "Fixture-only" means every row of data is sample data authored in the repository (`src/data/*.ts`, `src/services/data/mock/fixtures/*.ts`, `src/services/sdc/fixtures.ts`, `src/services/planning/somoFixture.ts`). There is no server, no database, no real sign-in and no live integration. A user's actions are real in one specific sense: they run through a command dispatcher with module, role, scope, legality and policy checks, mutate in-memory stores, and emit audit events. Reload the page and the in-memory state is gone (nine `localStorage` keys exist, listed in D4 §5; v2 said six, which was true at its pin).

**It is not a system of record.** SAP S/4HANA owns purchase orders, goods receipts, invoices, contracts, the vendor master and the material master. SOMO owns demand, the plan and the reorder point. Since MD-1 (#434) the portal holds a **replica** of SAP's master data that it reads and never writes (`docs/contracts/C13-master-data.md`); every record in it is stamped SAMPLE today. Since MD-4 + MD-5 (#439) a change to master data is a **request** (`masterDataRequest`): proposed, reviewed under four eyes, handed to SAP as a package and closed by SAP's answer. No act of that flow writes a master record; SAP is not connected, so the hand-off produces the package and stops (C13 §8). The portal owns the collaboration record: confirmations, declarations, uploads, review decisions, forecast publications to suppliers, and the trail of who was asked what. Every act the portal refuses to originate is declared as data on the verb (`surfaceable` in `src/services/transitions/schema.ts`). That table is rendered at `/buyer/process-flows`. Since PR #392 a source gate refuses any client-side construction of a governed document number (`src/lib/documentNumberGate/documentNumberGate.test.ts`; C11 V15 is now `GATE`).

**What the frontend specifies.** Read `src/services/data/types.ts` (the `IDataService` service contract), `src/services/transitions/flows/*.flow.ts` (the state machines), `docs/contracts/C1…C13`, and the six design documents under `docs/designs/` (`DESIGN_1…6`). One of the six is overtaken in part: `DESIGN_6_FLOW_BUILDER.md` says the Flow Builder "is not a runtime process engine" (its §1.2) and recommends promotion as generated, reviewed code (its §12, decision D1) — what v2's decision register summarised as "no runtime override" — and the operator reversed that on 2026-10-12 (§4, SE-16; D6 §2b). The design that replaces it for runtime changes, `docs/designs/DESIGN_6_v2.md`, is committed with v3, together with its plan and open decisions (`FB_BUILD_PLAN.md`, `FB_OPEN_DECISIONS.md`) and the master-data design set (`MASTER_DATA_DESIGN.md`, `MD_BUILD_PLAN.md`, `MD_OPEN_DECISIONS.md`). The backend is built against these; pages are meant not to change when the real service lands behind `DataServiceContext.tsx`.

## 2 · How to read the platform in one hour

1. **Ten minutes — run it.** `npm ci && npm run build && npm run preview` (Node 24, per `package.json` `engines` and `.nvmrc`), then open the printed URL. You are the buyer seat holding every buyer lane. The avatar opens the identity panel (`src/components/layout-v2/IdentityPanel.tsx`), where you switch persona, narrow roles, or act as a role-named sample person (`src/services/identity/sampleRoster.ts`; a role and an ordinal, never a name).
2. **Ten minutes — the process map and the guides.** `/buyer/process-flows` renders every flow and verb, and since PR #390–#391 a process guide per flow in English and Indonesian (`docs/guides/<entity>.<en|id>.md`, compiled at build into `src/guides/generated/guides.json`). The English guide is authoritative; the Indonesian guide carries a draft banner (`GUIDE_DRAFT_LOCALES = ['id']`, `src/guides/index.ts`). *v3:* the page has two views. **Catalogue** is the page as it was, and each flow says which version is in force. **Changes** lists every change to a process, the rules a change must obey, and opens the composer and the review (the Flow Builder; start with `docs/guides/flowVersion.en.md` and `processStep.en.md`).
3. **Ten minutes — the modules.** `/buyer/platform/modules` (roadmap board) and `/buyer/platform/modules/admin` (switch modules on or off; PRs #388–#389). A module that is off makes its routes read-only and its verbs refuse `MODULE_INACTIVE`. *v3:* `/buyer/master-data` (Platform group) shows the replica of SAP's master data: materials, suppliers and reference tables, each record with its stamp and where it is used. Since #439 it has two more views, **Change requests** and **Sync log**; a record's drawer offers "Propose a change" and the header "Ask for a new material" (start with `docs/guides/masterDataRequest.en.md`).
4. **Fifteen minutes — one verb end to end.** Follow `t_po_confirm`: the verb in `src/services/transitions/flows/purchaseOrder.flow.ts`, its adapter in `MockCommandService.ts`, the hook in `src/services/query/commandHooks.ts`, the button in `src/pages-v2/SupplierOrders.tsx`, the event in `src/services/transitions/events.ts`. D2 walks this in detail.
5. **Ten minutes — the contracts.** C1 (method surface), C3 (event shape), C5 (seams), C12 (what the backend must and must not do), C13 (the master-data replica, new). D7 says which of the thirteen are pinned and which carry stale text.
6. **Five minutes — the gates.** `npm run gates` runs the four checks CI runs (`scripts/gates.mjs`, `.github/workflows/gates.yml`). There is no lint script; do not add one without reading `CLAUDE.md`'s reason.
